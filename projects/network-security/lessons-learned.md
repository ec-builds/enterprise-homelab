## 2026-07-24 — Validate Generated VPN Configurations Before Customizing Them

**Context**

While configuring WireGuard on an ASUS router, the client configuration page presented both an Address field and a Server field. I initially assumed the Server field should contain the VPN server's address, which resulted in clients being unable to connect. Comparing the configuration against the default ASUS-generated values showed that both fields were expected to use the values generated by the router.

**Lesson**

Validate a known-good, vendor-generated configuration before changing network parameters based on assumptions about field names or expected behavior.

**Result**

- Restored the default ASUS-generated WireGuard configuration and verified successful client connectivity.
- Isolated the configuration change that had prevented the VPN tunnel from establishing.
- Changed the VPN subnet only after establishing a known-good baseline.
- Aligned the VPN addressing scheme with the internal network design to simplify future firewall rules and routing.
- Prepared the VPN configuration for cleaner integration with future VLANs and network segmentation.
