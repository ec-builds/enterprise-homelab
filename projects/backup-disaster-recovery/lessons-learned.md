# Lessons Learned

Lessons learned while building the Backup & Disaster Recovery Lab.

| Date | Summary | Context | Takeaway |
|---|---|---|---|
| 2026-11-24 | **Check What a Service Actually Listens On** | `upsd.conf` had both `LISTEN 127.0.0.1 3493` and `LISTEN 0.0.0.0 3493`. Once `upsd` bound localhost, binding all addresses on the same port failed quietly, so clients got `Connection refused` while the server looked healthy locally. `ss -tlnp` showed it listening on `127.0.0.1` only. | Verify the bound address with `ss` after configuring a network service, and keep only the wildcard line. `Connection refused` points at the listener or the address; a hang or timeout points at a firewall. |
| 2026-11-24 | **USB Permission Rules Apply on Plug-In** | The NUT driver failed with `insufficient permissions on everything` because the UPS was plugged in before NUT was installed, so the package's udev rule hadn't been applied to it. Re-triggering udev (`udevadm trigger`) gave the device to the `nut` group, and the driver connected. | When a driver can't open a device that's already plugged in, check its group and re-trigger udev before suspecting the hardware or the config. |
| 2026-11-24 | **Prove Recovery Settings Under the Final OS** | The Mac mini's power-on-after-power-loss setting had been tested under macOS. On Linux, that behavior depends on a chipset register macOS used to set at every boot. It still read on under Linux, and a fresh unplug test confirmed it; a boot-time service now sets it as a safeguard. Write-up: [Mac Mini Auto Power-On Under Linux](../../docs/reference/mac/mac-linux-auto-power-on.md). | A test under a previous OS doesn't prove behavior under the current one. Recovery settings have to be retested after a rebuild, because a machine that stays off after an outage defeats the whole shutdown plan. |
| 2026-11-24 | **Order the Rollout So Every Stage Is Safe** | Enabling the server's commit timer and outlet power-cycle before the clients were configured would have cut power to running Proxmox nodes and the NAS during an outage longer than five minutes. Clients were added first, because on their own they only react to the server. | When a change can act on other systems, configure the systems that receive the action first, so each intermediate state is no worse than the one before. |
| 2026-11-25 | **Vendor Defaults Aren't Shaped for Every Destination** | DSM's custom webhook defaulted to a `text` body, the format Slack and Synology Chat use. Discord requires `content` and rejects the message otherwise. DSM's Warning rule also turned out to include critical events, so a second webhook on the Critical rule would have sent every critical alert twice. | Check a webhook's body against the receiving service's API, and check what a built-in rule includes before layering a second one on top. |
